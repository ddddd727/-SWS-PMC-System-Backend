# Git 提交信息风格说明

本文档约定本项目 Git 提交信息的格式与风格，便于统一历史记录与回溯。

---

## 格式要求

1. **提交类别**：在首行标明大体类别，例如：
   - `feat`：功能新增或增强
   - `fix`：Bug 修复
   - `docs`：文档
   - `refactor`：重构
   - `chore`：构建/工具/杂项  
   可选用括号注明模块，如：`feat(PipeSpec)`、`fix(Auth)`。

2. **简要介绍**：紧接类别后，用一句话概括本次提交的主要变动（可多句，但保持简洁）。

3. **不写细项**：不在此风格下罗列「细项变更」清单；若需细节，可在提交说明正文中简要补充。

---

## 示例

```
feat(PipeSpec): 管附件标准接口增强与材料牌号查询

管附件标准接口支持按部件类型 ID 或名称查询，并移除专用 DTO，改为直接返回标准名称字符串列表；新增材料牌号列表接口，从 S3D 视图 S3D_CL_MaterialsGrade 读取并返回 ShortStringValue；同步更新 API 契约文档与请求校验。
```
